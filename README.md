# RegionFence

RegionFence is an adaptive concurrency control mechanism for parallel execution of Ethereum blocks.
Its unit of concurrency control is the region: the part of a transaction from its first observation
of a contended key to its last write to that key, or to transaction end if it never writes the key.
This repository holds the engine, the two baselines, data acquisition and experiment scripts,
and the CSV inputs and rendered figures of the paper.

## Layout

| Path | Contents |
|---|---|
| `engine/` | The RegionFence engine, the OCC (Block-STM) and PCC baselines, and serial replay |
| `cmd/rfreplay` | Replays blocks through an engine and checks every block against the chain |
| `cmd/rfsynth` | Generates the synthetic ERC20 and DeFi-Mix workloads |
| `scripts/` | Trace definitions, data fetching, synthetic workload generation |
| `experiments/` | `run.py` runs the experiments, `export.py` turns results into CSV files |
| `figures/` | `plot.py`, the CSV files in `data/`, and the rendered figures |
| `third_party/` | The patch applied to go-ethereum v1.17.6 |

## Requirements

- Go 1.25 or later, Git, and Python 3; matplotlib is needed only for plotting.
- Linux with `numactl` and `taskset` for `experiments/run.py`.
- An Alchemy Ethereum archive RPC account with `eth_getBlockReceipts` and
  `debug_traceBlockByNumber` / `prestateTracer` access for fetching mainnet data.
- A machine with at least 128 physical cores for the full core sweep. The runner binds to
  CPU IDs `0` through `P-1` and NUMA memory node `0`; check that these CPU IDs correspond to
  distinct physical cores on the benchmark host.
- Sufficient RAM for the workloads: the runner sets a 65,536 MiB Go soft memory limit,
  which is not a cap on total process or system memory.

## Setup

Run the commands below from the repository root.

```bash
git clone https://github.com/ictbc-feng/RegionFence.git
cd RegionFence
sh setup.sh
go build -o rfreplay ./cmd/rfreplay
go build -o rfsynth ./cmd/rfsynth
```

`setup.sh` fetches go-ethereum v1.17.6 into `third_party/go-ethereum` and applies the patch, which
lets the engine reuse `StateDB` objects between transactions.

## Artifact availability

The source, dependency lockfile (`go.sum`), go-ethereum patch, experiment configurations,
plotting scripts, figure CSV inputs, and rendered PDFs are included in this public repository.
The input fixtures under `data/` and per-run measurements under `results/` are generated by
the commands below and are not bundled in Git. Synthetic workloads use seed `1` by default.
Mainnet input data is retrieved from the public Ethereum chain through Alchemy; obtaining an
account and sufficient archive/debug API access is a separate requirement and may incur
provider charges. No RPC credential is included in this repository.

To inspect or redraw the supplied figures, no mainnet data, RPC account, Go build, or
benchmark hardware is required:

```bash
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install matplotlib
python3 figures/plot.py
```

This redraws `figures/figure_a.pdf` through `figures/figure_g.pdf` from the supplied CSV files.
To produce new measurements, follow Setup, Data, and Experiments in order; rendering the
supplied CSVs alone does not rerun the experiments. Absolute timings depend on the host.

## Experiments

```bash
python3 experiments/run.py positions
python3 experiments/run.py scaling
python3 experiments/run.py control
python3 experiments/run.py mechanism
python3 experiments/run.py synth
```

Each item runs on exactly P physical cores with P workers. `run.py` refuses to start unless the
performance governor is set (`cpupower frequency-set -g performance`). Keep the machine otherwise
idle. Finished items are skipped, so an interrupted run can be restarted. A run fails if any block
differs from the chain. Each timed configuration is repeated three times and reports its
median. Logs and completed JSONL measurements are written under `results/<experiment>/`.
Use a fresh results directory for an independent rerun because completed items are skipped.
The mechanism run uses one instrumented repetition instead of the timed protocol.

| Experiment | Figures | Notes |
|---|---|---|
| `synth` | A | Three engines, core sweeps and parameter sweeps |
| `scaling` | C, D | Three engines, 1 to 128 cores, all traces |
| `control` | G(a) | 64 cores, with and without learning |
| `mechanism` | E, F, G(b, c) | All traces in one process with the timeline on. Do not use its wall time |
| `positions` | C | Access positions and serial times for the limit |

Figure B needs no experiment: it comes from the fetched data.
